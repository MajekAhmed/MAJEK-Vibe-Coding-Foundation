# Engineering Baseline
- Prefer simple, maintainable solutions over premature abstraction.
- Adopt a project's stack only during its separate onboarding.
- Pin dependencies in the consuming project; avoid unnecessary global installs.
- Keep configuration explicit and environment-specific.
- Separate source, tests, documentation, and generated artifacts.
- Use meaningful names, small changes, and behavior-focused tests.
- Handle errors explicitly and document non-obvious decisions.
- These are defaults, not a mandate to impose one stack on future projects.
